## Reference dial sequence and local correction

Rechecked upstream at [`841d0428eadf7e99ddc85d57f0d9026a86b14566`](https://github.com/LianXia233/luci-app-mt5700/tree/841d0428eadf7e99ddc85d57f0d9026a86b14566). The relevant files are [`src/rust/src/atclient.rs`](https://github.com/LianXia233/luci-app-mt5700/blob/841d0428eadf7e99ddc85d57f0d9026a86b14566/src/rust/src/atclient.rs), `root/etc/init.d/at-webserver`, `root/usr/libexec/at-webserver/on-uplink.sh` and the USB hotplug hook. The Rust AT client operates independently of a netdev, queries autodial, enables USB mode using `AT^SETAUTODIAL=1,1`, reads it back, and retries with backoff. An already aligned or short enabled reply does not cause repeated writes. The ready callback starts ordinary DHCP/DHCPv6 interfaces; the init script retries ifup and checks actual addresses. The reference Makefile supplies no special vendor-NCM driver dependency. It does not automatically change SETMODE or synthesize a static lease from CGPADDR.

Our 3.9.26 sequence instead returned NETDEV_MISSING before reaching AT dial when no netdev existed, and autodial=0 used manual NDISDUP. This is a confirmed control-flow error, independent of whether enabling autodial also resolves this particular USB enumeration.

The local correction dispatches MT5700 before the generic netdev check. It selects USB, rediscovers PCUI under the configured physical USB path, checks registration and roaming permission, restores saved bands, then enables/verifies USB autodial before looking for that modem's netdev. An initially disabled context is prepared from the configured CID 1 APN/PDP and optional PAP/CHAP authentication. Existing enabled contexts retain modem-owned APN settings. Six attempts use 0/5/10/15/30/60-second delays, with an elapsed-time check before each attempt; AT transactions have individual lock waits and command timeouts. No lock spans backoff or band restoration.

Once the data link is ready, netifd manages persistent DHCP `_4` and DHCPv6 `_6` children according to the actual CID 1 PDP type, including the parent's zone and route defaults. No manual NDIS teardown or CGPADDR static fallback remains in this branch. Missing/unparseable activation status permits DHCP; explicit CID 1 inactivity causes a retry (another CID's IMS context does not count). Parent link-up is not evidence of an acquired address. Hotplug ignores netdev-add while setup is pending, so enumeration cannot cancel the AT bootstrap.

Failures retain a specific startup phase and remain retryable. A captured ff/02/16 interface with no network device after startup reports TDTECH_VENDOR_NCM; this is still an unresolved driver/data-path case, not proof that a particular driver should be forced. The diagnostic collector now records live configuration/interface descriptors and bound drivers to distinguish this case in the next report.

Offline regression coverage includes enabling before netdev lookup, a rejected first attempt, autodial readback, disabled-context preparation, CID-specific activation, busy/timeout AT locking, DHCP child selection and creation failure, bounded missing-netdev behavior, roaming refusal and the pending-hotplug guard. These checks do not replace a cold-boot/lease/traffic test on the user's modem.
