## Reference dial sequence and local correction

Rechecked upstream at [`841d0428eadf7e99ddc85d57f0d9026a86b14566`](https://github.com/LianXia233/luci-app-mt5700/tree/841d0428eadf7e99ddc85d57f0d9026a86b14566). The relevant files are [`src/rust/src/atclient.rs`](https://github.com/LianXia233/luci-app-mt5700/blob/841d0428eadf7e99ddc85d57f0d9026a86b14566/src/rust/src/atclient.rs), `root/etc/init.d/at-webserver`, `root/usr/libexec/at-webserver/on-uplink.sh` and the USB hotplug hook. The Rust AT client operates independently of a netdev, queries autodial, enables USB mode using `AT^SETAUTODIAL=1,1`, reads it back, and retries with backoff. An already aligned or short enabled reply does not cause repeated writes. The ready callback starts ordinary DHCP/DHCPv6 interfaces; the init script retries ifup and checks actual addresses. The reference Makefile supplies no special vendor-NCM driver dependency. It does not automatically change SETMODE or synthesize a static lease from CGPADDR.

Our 3.9.26 sequence instead returned NETDEV_MISSING before reaching AT dial when no netdev existed, and autodial=0 used manual NDISDUP. This is a confirmed control-flow error, independent of whether enabling autodial also resolves this particular USB enumeration.

The local correction dispatches MT5700 before the generic netdev check. It selects USB, rediscovers PCUI under the configured physical USB path, checks registration and roaming permission, restores saved bands, then enables/verifies USB autodial before looking for that modem's netdev. An initially disabled context is prepared from the configured CID 1 APN/PDP and optional PAP/CHAP authentication. Existing enabled contexts retain modem-owned APN settings. Six attempts use 0/5/10/15/30/60-second delays, with an elapsed-time check before each attempt; AT transactions have individual lock waits and command timeouts. No lock spans backoff or band restoration.

Once the data link is ready, netifd manages persistent DHCP `_4` and DHCPv6 `_6` children according to the actual CID 1 PDP type, including the parent's zone and route defaults. No manual NDIS teardown or CGPADDR static fallback remains in this branch. Missing/unparseable activation status permits DHCP; explicit CID 1 inactivity causes a retry (another CID's IMS context does not count). Parent link-up is not evidence of an acquired address. Hotplug ignores netdev-add while setup is pending, so enumeration cannot cancel the AT bootstrap.

Failures retain a specific startup phase and remain retryable. A captured ff/02/16 interface with no network device after startup reports TDTECH_VENDOR_NCM; this is still an unresolved driver/data-path case, not proof that a particular driver should be forced. The diagnostic collector now records live configuration/interface descriptors and bound drivers to distinguish this case in the next report.

Offline regression coverage includes enabling before netdev lookup, a rejected first attempt, autodial readback, disabled-context preparation, CID-specific activation, busy/timeout AT locking, DHCP child selection and creation failure, bounded missing-netdev behavior, roaming refusal and the pending-hotplug guard. These checks do not replace a cold-boot/lease/traffic test on the user's modem.

Validation: 52 Python issue regression tests passed; all 16 MT5700 metric/band profile smoke scenarios passed. BusyBox ash syntax checks passed for the modified shell entry points and helper; git diff whitespace checks passed. No hardware connection or traffic test was available.

Missing/unparseable registration now has its own retryable TDTECH_REGISTRATION_UNAVAILABLE phase and identifies the actual selected PCUI path in the log. The 18:50 report confirms an active IPv4 lease on dynamic modem2_4, a default route through eth4 and working DNS. This is hardware confirmation of the repaired AT startup, USB autodial and DHCPv4 path, not yet IPv6 validation.

A precise mismatch remains: UCI modem2.pdptype is IPV4V6, but CID 1 is `IP` with the configured APN, SETAUTODIAL reports an enabled USB profile with protocol IP, and NDIS reports IPv4 active / IPv6 inactive. Dynamic modem2_6 does not exist. The prior handler returned early for enabled USB autodial, preserving the old modem profile even when OpenWrt settings changed. It then selected DHCP children using the live IP context, suppressing the IPv6 client. Running DHCPv6 alone cannot provide an IPv6 context that the modem was never asked to establish.

The local correction compares the configured full profile with SETAUTODIAL readback and applies the documented full setter on mismatch, including when autodial is already enabled. The command shape, PDP choices and authentication codes were rechecked in upstream [`dial.js`](https://github.com/LianXia233/luci-app-mt5700/blob/841d0428eadf7e99ddc85d57f0d9026a86b14566/htdocs/luci-static/resources/view/at-webserver/dial.js). Matching profiles are left alone. Full readback preserves spaces/commas inside quoted credentials. Short replies are checked against CID 1 protocol/APN; credential verification is limited when firmware omits them. Query failures do not prevent attempting a complete configured setter, but successful readback is required. Invalid AT-string delimiters/control characters, unsupported PDP values and fields exceeding documented lengths are rejected before sending. No credentials are added to logs.

DHCP children now follow the requested protocol instead of racing the old CID 1 context immediately after a profile update. IPV4V6 starts DHCP4 and DHCPv6; IP and IPV6 each start the corresponding client. This requests service and allows negotiation to finish; it does not manufacture an address or guarantee carrier IPv6 support. There is no automatic NDIS disconnect or USB driver change.

The report also contains a separate static DHCPv6 interface named modemv6, attached to @modem2, repeatedly failing with `ubus error: Invalid argument`. It has no successful IPv6 lease. This interface is not created by the TD helper (which uses modem2_6), and the report does not establish which option or platform component causes its invalid-argument loop. Before testing the normal dynamic IPv6 child, this redundant manual client should be disabled by its owner. The correction does not silently delete user-created interface configuration.

The later screenshot shows `Installing dbus` followed by `chown: /etc/dbus-1: No such file or directory`, not a missing ubus network driver. It is an error from that dependency's installation stage; the screenshot ends before installation finishes. The earlier 18:50 report explicitly says ubusd is running and ubus answers, so that earlier working system did not lack ubus. It does not prove the outcome of the later fresh installation. No causal link between that screenshot and the modem's IPv4-only PDP is established.

The reporter also asks whether a system/kernel upgrade or replacement OpenWrt installation will retain support. The addon scripts are architecture-independent, while host kernel modules must be available for the installed kernel. This report confirms only the tested kernel/system combination. It cannot guarantee arbitrary third-party builds or vendor-NCM support on a changed kernel; preserve working CDC NCM bindings and verify driver/package compatibility after an upgrade.
