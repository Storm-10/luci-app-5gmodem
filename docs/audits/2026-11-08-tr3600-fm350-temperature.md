# FM350 temperature missing on Cudy TR3600

Source: private report `zews_nk/5gmodem-diag-20261108-0243.txt`, reviewed on 2026-11-08. Subscriber/device identifiers are omitted here.

## Evidence

- Cudy TR3600 v1, OpenWrt 25.12.6, mediatek/filogic; app 3.9.25-r1.
- Fibocom FM350-GL, USB 0e8d:7127, firmware 81600.0000.00.29.24.02; metrics port ttyUSB1.
- The modem is connected and probes pass. Serving-cell/signal metrics are present. The seven-second-old snapshot already contains mtemp="-" and temps="-".
- ModemManager is disabled/excluded and usb_flaps is zero. The report has no raw ETHERMAL answer, error or timeout.

## Code path

`modem/usb/0e8d7127` reads the modem temperature using `AT+ETHERMAL?` on its AT port. It does not read the router's thermal_zone/hwmon sensors, and this path has no TR3000/TR3600 branch. The report therefore establishes neither a router temperature-driver problem nor a frontend-only fault: the backend temperature is already absent.

The parser takes the highest second comma-separated field after the ETHERMAL marker, between -40 and 120 Celsius. Implausible jumps are held until repeated. With no usable fresh answer it publishes no temperature. Missing/rejected/timed-out responses, only invalid readings and unsupported response formats can all produce this result; the current report cannot distinguish them.

## Initial evidence request (superseded by local source review)

Obtain the complete raw `AT+ETHERMAL?` result from the app's AT console on ttyUSB1, including ERROR or timeout. The console uses the app's port queue. Preserve an unexpected answer as a regression fixture before changing the parser. A working TR3000 result and modem firmware would help a comparison but are optional for the first check.

The collector now includes this read-only query for FM350 USB IDs 0e8d:7126 and 0e8d:7127, selected by the queried port's own USB ancestry. The supplied report predates that instrumentation. No speculative router-specific workaround was added.

The confirmed application gap is that temperature had only one command path, ETHERMAL, despite an available documented alternative with a captured live reply. This does not establish why ETHERMAL is silent on the reporter's particular setup, or prove that a TR3600-specific router thermal driver is involved.

The correction preserves existing valid ETHERMAL readings and queries `AT+GTSENRDTEMP=1` only when none is available. It accepts only the expected sensor ID and an integer value, converts millidegrees to one decimal Celsius, filters implausible results, and applies the existing three-confirmation jump filter. Empty or malformed ETHERMAL values no longer become a fabricated zero that would suppress the fallback. Both FM350 USB IDs share this profile. The fallback reads modem SoC temperature; it is not the router's own CPU temperature or a guarantee of the hottest PA sensor.

The diagnostic collector captures both commands on the modem's own port, and the AT command menu offers the alternative. No thermal-management enable, threshold, actuator or throttling settings are changed. Full per-sensor display and GTZONERDMAXTEMP remain separate work; they are unnecessary for the evidenced fallback.
